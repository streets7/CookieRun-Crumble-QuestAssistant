# 5회 스테이지 반복 및 실행 로그 복구 설계

## 의도

통합 자동 순환의 시작 조건을 시간 경과가 아니라 같은 스테이지의 실제 보스 소환 재시도 5회로 변경한다. 프로그램 재시작 직후 관리자 인증 응답이 엇갈려 실행 로그가 사라지는 문제도 함께 해결한다.

## 동작

- 같은 스테이지에서 보스 소환 버튼을 실제 누른 횟수만 센다.
- 1~4회에는 통합 작업을 실행하지 않고, 5회째에 한 번 실행한다.
- 퀘스트 완료, 다른 화면, 다른 스테이지로 전환되면 횟수를 초기화한다.
- 통합 작업 후 같은 스테이지를 다시 5회 반복하면 다음 점검 창을 열 수 있다.
- 관리자 상태 조회는 요청 시작 시의 인증 토큰과 현재 토큰이 같을 때만 화면에 반영한다.

## 접근 방식

- 선택: 기존 추적기를 시간 추적에서 실제 시도 횟수 추적으로 변경하고, 보스 소환 직전에 전용 이벤트를 보낸다.
- 제외: 화면 확인 반복 횟수는 프레임 속도에 따라 달라져 실제 플레이 반복을 뜻하지 않으므로 사용하지 않는다.
- 제외: 3분 기준과 5회 기준을 동시에 유지하면 실행 시점을 예측하기 어려워지므로 시간 기준은 제거한다.

## 검증

- 4회까지 미실행, 5회째 실행, 완료·화면·스테이지 변경 시 초기화 검사.
- 오래된 비관리자 응답이 새 관리자 세션을 덮지 못하는 화면 검사.
- 전체 Python 및 화면 검사, 설치 앱 자체 검사.
