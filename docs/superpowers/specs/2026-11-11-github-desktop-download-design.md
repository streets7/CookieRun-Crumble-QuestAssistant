# Mac·Windows 데스크톱 프로그램 전환 설계

## 목적

현재 브라우저에 표시되는 화면을 Mac과 Windows에서 각각 설치해 실행하는 데스크톱 프로그램으로 전환한다. 사용자는 GitHub Release에서 자신의 운영체제에 맞는 설치 파일을 선택하고, 설치 후에는 브라우저 없이 전용 프로그램 창에서 도우미를 사용한다.

## 선택한 방식

기존 Python 자동화 엔진과 검증된 화면 구성을 유지하면서, 운영체제별 데스크톱 창 안에 화면을 표시한다. GitHub는 소스 저장, 자동 빌드, 최신 정식 버전 확인 및 설치 파일 배포에만 사용한다.

검토한 다른 방식은 화면을 완전한 네이티브 UI로 다시 작성하는 방법과 하나의 통합 설치 파일이다. 완전 재작성은 현재 기능을 깨뜨릴 위험과 작업량이 크고, 통합 설치 파일은 Mac과 Windows 실행 형식이 달라 만들 수 없으므로 제외한다.

## 프로그램 구성

- 프로그램 아이콘을 누르면 브라우저가 아니라 독립된 전용 창이 열린다.
- 자동화 엔진과 내부 화면 서버는 프로그램 내부에서만 함께 실행한다.
- 기존 일반 화면, 관리자 모드, 오늘의 총정리, 오류 보고를 유지한다.
- 창을 닫으면 실행 중인 자동화를 안전하게 중지하고 내부 서버도 종료한다.
- 상단에서 현재 버전, BlueStacks 연결 상태, 업데이트 가능 여부를 확인한다.
- Mac은 Apple Silicon과 BlueStacks Air를 지원하는 DMG로 배포한다.
- Windows는 Windows 11과 BlueStacks 5를 지원하는 설치형 EXE를 목표로 한다.

## 배포 흐름

1. 정식 버전 태그를 만든다.
2. GitHub Actions가 macOS와 Windows에서 각각 검사하고 프로그램을 빌드한다.
3. Mac DMG와 Windows 설치 파일, 체크섬, 변경 내용을 같은 GitHub Release에 등록한다.
4. 사용자는 GitHub Release에서 Mac 또는 Windows 파일을 직접 선택한다.
5. 프로그램은 GitHub의 최신 정식 Release만 확인해 새 버전 알림을 표시한다.
6. 베타 버전은 사용자가 별도로 요청할 때만 만든다.

## 안전장치

- 빌드 또는 검사 실패 시 Release 파일을 발행하지 않는다.
- 내부 서버는 외부 네트워크에 공개하지 않고 로컬에서만 사용한다.
- 프로그램 창을 여러 번 열어도 자동화 엔진과 내부 서버가 중복 실행되지 않게 한다.
- 관리자 비밀번호, 계좌 정보, 개인 설정 및 오류 스크린샷은 저장소와 배포 파일에 포함하지 않는다.
- Windows는 실제 Windows 환경 검증이 끝나기 전까지 `검증 필요` 안내를 유지한다.

## 범위 밖

- 무인 자동 업데이트 설치
- Apple 공증과 유료 코드 서명 인증서 구매
- 완전한 네이티브 UI 재작성
- GitHub 외 별도 서버 운영

## 선행 조건

현재 로컬 프로젝트에는 GitHub 원격 저장소와 커밋이 없고, 연결된 GitHub 계정에서도 접근 가능한 저장소가 확인되지 않았다. 따라서 구현 후 실제 공개 전에 새 저장소 생성, 공개 범위 선택, 최초 업로드가 필요하다.
