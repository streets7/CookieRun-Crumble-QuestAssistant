# 관리자 오늘의 총정리 설계

## 목적

관리자가 오늘 자정부터 수행한 자동 작업을 여러 로그와 화면을 오가지 않고 한 팝업에서 확인한다. 프로그램을 종료하거나 다시 실행해도 당일 기록은 유지한다.

## 범위

- 관리자 로그인 후 `오늘의 총정리` 버튼을 표시하고 기존 관리자 팝업 방식으로 연다.
- 팝업에는 날짜·버전·현재 상태, 실행 시작 횟수, 완료 수, 오류 수, 복구 수, 오늘 선택한 작업, 최근 활동, 아레나 덱 판단을 표시한다.
- 데이터는 사용자 데이터 폴더의 `daily_summary.json`에 날짜별로 저장하며 최근 31일만 보관한다.
- 비밀번호, 계좌 정보, 전체 오류 로그와 스크린샷 내용은 총정리 파일에 저장하지 않는다.
- 관리자 인증이 확인된 `/status` 응답에만 총정리 데이터를 포함한다.
- 새 실행을 시작해도 오늘 누적 기록은 초기화하지 않는다. 날짜가 바뀌면 새 날짜 항목을 사용한다.
- 아레나에서 도전 가능한 덱이 없으면 1번 주덱을 다시 선택하고, 덱별 판독·도전 여부를 오늘의 아레나 판단 목록에 기록한다.
- Windows 실제 실행과 GitHub 연결 여부는 자동으로 추측하지 않고, 배포 검증 상태를 `Mac 검증 완료 / Windows 실제 검증 필요 / GitHub 연결 필요`로 표시한다.

## 기록 방법

- 실행 시작과 선택 작업은 시작 요청 처리 시 구조화해 기록한다.
- 완료 수는 기존 진행 보고 값의 증가분을 누적한다.
- 오류는 기존 오류 보고 저장 지점에서 누적한다.
- 복구 성공과 주요 활동, 아레나 판단은 출력 문구를 제한된 규칙으로 분류해 최근 50개만 보관한다.
- 파일 저장은 임시 파일을 쓴 뒤 교체해 중간 종료로 파일이 깨질 가능성을 줄인다.

## 화면 구성

- 상단: `2026-11-11 오늘의 총정리`, 현재 버전과 실행 상태
- 요약 카드: 실행, 완료, 오류, 복구
- 선택 작업: 오늘 실행 요청에 포함된 작업별 횟수
- 아레나 판단: 덱 번호, 내 전투력, 상대 전투력, 판단 결과
- 최근 활동: 최신순 시각과 짧은 설명
- 배포 상태: Mac·Windows·GitHub 확인 상태
- 하단: 새로고침과 텍스트 복사 버튼

## 고려한 방식

1. 날짜별 구조화 저장: 재시작 후에도 유지되고 정확한 집계가 가능해 선택했다.
2. 현재 실행 상태만 표시: 간단하지만 하루 전체를 볼 수 없어 제외했다.
3. 기존 로그 전체를 매번 분석: 이전 로그에는 적용하기 쉽지만 문구 변경에 취약해 제외했다.

## 검증

- 관리자 미인증 응답에 총정리가 노출되지 않는지 확인한다.
- 날짜별 누적, 재시작 후 로드, 31일 정리, 손상 파일 복구를 검사한다.
- 실행·완료·오류·복구·아레나 판단 기록과 팝업 렌더링을 검사한다.
- 기존 Python 및 UI 검사를 모두 실행하고 Mac 설치본 자체 검사와 DMG 검증을 수행한다.
