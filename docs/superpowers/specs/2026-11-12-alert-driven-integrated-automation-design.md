# 알림 반응형 통합 자동화 설계

## 목적

기존 퀘스트 자동 완료가 스테이지에서 3분 이상 진척되지 않을 때, 게임의 빨간 알림과 활성화된 무료 버튼을 기준으로 부가 작업을 안전하게 처리하고 다시 기본 퀘스트 매크로로 복귀한다. 사용자가 여러 매크로를 따로 실행하지 않아도 하루 단위 콘텐츠와 간헐적 성장 작업이 한 흐름에서 동작해야 한다.

## 목표

- 동일 퀘스트의 스테이지 완료 대기가 3분 지속되면 통합 점검을 시작한다.
- 통합 점검 중에도 유료 재화 사용, 상점, 뽑기, 연구 기부, 도감, 노움 연구소, 스텔라 링크는 실행하지 않는다.
- 빨간 알림이나 명확한 무료 활성 버튼이 있는 메뉴만 처리한다. 단, 던전 아이콘의 빨간 알림은 아레나 때문에 상시 표시될 수 있으므로 후보 판별에 사용하지 않는다.
- 일일 던전, 크럼블 던전, 임플란트 타워, 아레나는 알림이 없어도 하루 한 번 남은 횟수와 무료 상태를 확인한다.
- 각 작업의 성공·건너뜀·실패·다음 확인 시간을 날짜별 상태에 저장한다.
- 어느 단계에서든 화면 판별이 불확실하거나 유료 화면이 나타나면 해당 작업만 중단하고 전투 화면으로 복귀한다.

## 하지 않는 일

- 도감 확인
- 노움 연구소와 스텔라 링크
- 뽑기와 상점
- 길드 연구 기부
- 크리스탈을 사용하는 아레나 새로고침 또는 도전
- 화면 판별이 불확실한 상태에서 좌표만으로 연속 클릭

## 선택한 접근 방식

### 선택: 알림 반응형 + 네 가지 일일 확인 예외

메인 전투 화면에서 빨간 알림과 버튼 활성 상태를 먼저 감지하고, 신호가 있는 항목만 진입한다. 일일 던전·크럼블 던전·임플란트 타워·아레나는 알림에 의존하지 않고 하루 한 번 상태를 확인한다. 불필요한 메뉴 진입을 줄이면서도 일일 횟수를 놓치지 않는 방식이다.

### 검토했지만 선택하지 않은 방식

- 통합 고정 순환: 모든 메뉴를 차례로 방문하므로 확실하지만 실행 시간이 길고 불필요한 클릭이 많다.
- 고정 시간표: 구현은 단순하지만 게임 실행 상태 및 기본 매크로와 충돌할 수 있다.

## 실행 흐름

1. 기본 퀘스트 매크로가 현재 퀘스트와 스테이지 진행 상태를 기록한다.
2. 같은 스테이지 퀘스트가 완료·전환되지 않은 채 180초가 지나면 전투 화면을 기준점으로 복구한다.
3. 오늘의 상태 기록을 읽고 직접 확인 예외 중 아직 확인하지 않은 항목을 후보에 넣는다.
4. 메인 화면의 빨간 알림을 감지해 쿠키·펫·길드 후보를 추가한다. 던전 아이콘의 빨간 알림은 무시한다.
5. 후보를 `일일 던전 → 크럼블 던전 → 아레나 → 임플란트 타워 → 길드 → 쿠키 → 펫 → 성장` 순으로 처리한다.
6. 각 작업이 끝날 때마다 전투 화면으로 복귀하고 상태를 저장한다.
7. 후보가 없거나 모두 처리되면 기본 퀘스트를 처음부터 재판별한다.
8. 같은 스테이지가 계속 정체되어도 완료한 항목은 재실행하지 않고, 다음 확인 가능 시간이 된 항목만 다시 본다.

## 작업별 규칙

### 쿠키

- 메인 화면 쿠키 메뉴에 빨간 알림이 있을 때만 진입한다.
- 일괄 승급 버튼이 무료 재료 조건으로 활성화된 경우 한 번 처리한다.
- 편성팀 레벨업 가능 여부를 확인하고, 명확한 활성 버튼만 처리한다.
- 간헐 작업으로 기록하여 같은 날 한 번만 처리한다.
- 편성팀 레벨업은 현재 편성팀만 한 번 처리한다.

### 펫

- 메인 화면 펫 메뉴에 빨간 알림이 있을 때만 진입한다.
- 펫 쉼터의 `모두 받기`가 활성화된 경우 한 번 누른다.
- 받기 버튼이 비활성화되거나 화면이 다르면 즉시 복귀한다.
- 같은 날 한 번만 처리한다.

### 성장

- 돌파력은 코인 던전을 완료했고 코인 잔액이 설정된 안전 기준 이상일 때만 후보가 된다.
- 공격력 → 체력 → 방어력 순으로 각각 한 단계만 올리며, 각 버튼이 활성화된 경우에만 누른다.
- 명성은 아레나 무료 순환 후 명성 레벨업 버튼이 활성화된 경우 한 단계만 진행한다.
- 정확한 코인·명성 기준은 화면에서 현재 비용과 보유량을 함께 읽어 `보유량 >= 비용`일 때만 허용한다. OCR이 실패하면 실행하지 않는다.
- 코인 던전 처리 후 돌파력, 아레나 처리 후 명성을 성장 후보로 추가한다.

### 도전 던전

- 크럼블 던전은 하루 누적 완료 횟수를 읽고 4회 미만이면 남은 횟수만 실행한다. 이미 4회 이상이면 완료로 기록한다.
- 아레나는 무료 다음 상대와 무료 새로고침만 사용한다. 새로고침이 크리스탈 표시로 바뀌면 누르지 않고, 화면에 표시된 무료 전환 시각 또는 남은 시간을 기록한다.
- 임플란트 타워는 현재 850층 완료 여부를 확인한다. 완료했으면 영구 건너뜀 상태로 기록하고, 미완료면 진행하되 한 번 실패하면 당일 작업을 종료한다.

### 일일 던전

- 경험치 → 코인 → 반죽 → 연구석 → 룬결정 순서로 처리한다.
- 각 던전에서 오늘 사용 가능한 무료 횟수를 화면에서 읽고 그 횟수 안에서만 실행한다.
- 광고 입장은 계정의 광고 패스 보유 표시와 광고 패스 적용 상태를 모두 확인한 경우에만 사용한다.
- 광고 패스가 없거나 판별에 실패하거나 실제 광고 재생 화면으로 전환될 수 있는 상태라면 광고 입장을 누르지 않는다.
- 클리어에 실패하거나 진행 불가가 확인되면 달성 보상 중 무료 수령 버튼만 처리하고 다음 던전으로 이동한다.
- 마지막 룬결정 던전 후 전투 화면으로 복귀한다.

### 길드

- 메인 길드 아이콘에 빨간 알림이 없으면 진입하지 않는다.
- 도움 센터의 `한번에 돕기`가 활성화된 경우 한 번 처리한다.
- 길드 연구소의 `모두 연구 지원`이 활성화된 경우 하루 한 번 처리한다. 연구 기부 버튼은 누르지 않는다.
- 길드 지원 화면 오른쪽 아래 체크 표시가 없고 무료 수령 상태가 명확할 때만 지원을 받는다.

## 화면 조사 및 좌표 정책

- 현재 대상 기기는 세로형 `emulator-5554`, 기준 해상도 1080×1920이다.
- 구현 전에 각 메뉴를 실제로 열어 진입 화면, 활성·비활성 버튼, 유료 전환 상태, 복귀 버튼을 캡처한다.
- 조사 중에는 메뉴 이동과 화면 캡처만 허용한다. 보상 수령·레벨업·전투 시작처럼 상태를 바꾸는 버튼은 판별 자료가 확보되기 전 누르지 않는다.
- 좌표만으로 상태를 판단하지 않고 버튼 색상, 텍스트 OCR, 화면 고유 영역 중 최소 두 조건을 사용한다.
- 1080×1920 기준 좌표는 기존 크기 변환 함수를 통해 다른 지원 해상도로 변환한다.

## 상태 저장

날짜별 상태에는 다음을 저장한다.

- 마지막 정체 감지 시각과 퀘스트 식별자
- 일일 직접 확인 완료 여부
- 각 던전의 확인 횟수와 완료 횟수
- 아레나 무료 새로고침 재확인 가능 시각
- 임플란트 850층 완료 여부와 당일 실패 여부
- 쿠키·펫·길드·성장 마지막 처리 시각과 결과
- 마지막 안전 복귀 화면

날짜가 바뀌면 일일 항목을 초기화하되 임플란트 850층 완료 상태는 유지한다.

## 오류 및 안전 복구

- 화면 판별 실패: 추가 클릭 없이 뒤로가기로 전투 화면 복구 후 해당 항목을 건너뛴다.
- 유료 표시 감지: 버튼을 누르지 않고 비용 종류와 재확인 시간을 기록한다.
- 앱 종료 또는 Android 홈: 기존 자동 재실행을 사용하되 진행 중 항목을 재개하지 않고 전투 화면에서 다시 후보를 계산한다.
- 동일 항목이 하루 세 번 연속 실패하면 당일 비활성화하고 관리자 로그에 남긴다.
- 사용자가 정지하면 현재 대기와 화면 이동을 즉시 중단한다.

## 화면 구성

- 일반 화면에는 `통합 자동 순환` 체크와 `스테이지 정체 3분` 상태만 간단히 표시한다.
- 관리자 화면에는 항목별 오늘 상태, 마지막 확인 시각, 다음 확인 시각, 건너뛴 이유를 표시한다.
- 기존 개별 작업 실행은 유지하여 문제 발생 시 한 항목만 따로 검증할 수 있게 한다.

## 검증 기준

- 스테이지가 179초 정체되면 실행하지 않고 180초부터 한 번만 통합 점검을 시작한다.
- 빨간 알림이 없는 쿠키·펫·길드는 진입하지 않으며, 던전 아이콘의 빨간 알림은 항상 무시한다.
- 네 가지 예외는 하루 한 번 확인하며 완료된 항목은 반복하지 않는다.
- 화면별 허용 버튼 목록에 없는 좌표에는 탭이 발생하지 않으며, 유료 새로고침·연구 기부·상점·뽑기는 허용 목록에 넣지 않는다.
- 작업 실패 후 전투 화면으로 복귀하고 기본 퀘스트 자동 완료가 계속된다.
- macOS와 Windows가 같은 상태 파일 형식과 화면 판별 규칙을 사용한다.
